# V1 · Casos de validação (S1 fases 0 e 1)

Escritos pela SV **antes do código** da S1, em 26/10/2026. Método: `sessoes/SV-validacao.md`. Valida: S1 fase 0 (fundação) e fase 1
(venda direta no ar). A SV não construiu nada disto e não corrige código: erro achado volta pela S0.

## Regras desta rodada

- **Nunca produção, nunca dado real.** Só a prévia (`?demo=1`, `API_URL: 'simulada'`), o Postgres embutido
  (`npm run test:supabase`), os testes de unidade (`npm test`) e os e2e (`npm run test:e2e`). Pessoas, e-mails, telefones e
  pedidos usados são sempre inventados (`@exemplo.com`, telefones fictícios).
- **Prova** de cada caso em `provas/V1/<id>.md`: só contagens, status, nomes de arquivo e prints com dados fictícios. Nunca
  conteúdo de cópia do banco, chave, senha, token, e-mail ou telefone de verdade.
- **Passa** com 2 rodadas seguidas sem erro. Rodada = todos os casos abaixo rodados do zero. Erro corrigido recomeça a contagem.
- **Como** (coluna "Via"): `P` prévia · `B` Postgres embutido · `U` unidade (`npm test`) · `E` e2e · `L` leitura de código/texto ·
  `M` manual do dono ou da S1 com conta de teste (a SV só confere o resultado; nunca digita senha, chave ou token) ·
  `A` agente adversário (Haiku 5.5, baixo: tenta quebrar e varre texto).
- Casos marcados **P1** valem para o portão P1 (S1 fase 0: e-mail e backup). Os demais valem para o P2 (venda direta ao público).
- Situação inicial de todos: **a rodar** (esperando `status/S1.md`).
